# Security model

Digest takes a stranger's URL, fetches it from our server, and feeds the content to an LLM. That is three classic risks in one request, so security is a design input, not a layer added at the end.

## Assets and trust boundaries

| Asset                          | Where                   | Protection                                                                                    |
| ------------------------------ | ----------------------- | --------------------------------------------------------------------------------------------- |
| AI provider keys               | server environment only | never in the client bundle, URLs, logs or error bodies; redacted from logs; header-based auth |
| Free AI quota (shared, scarce) | providers               | rate limit, cache, fallback, breaker, size-aware routing                                      |
| Server network position        | Vercel function         | SSRF defence in depth (below)                                                                 |
| User privacy                   | browser, logs           | host-only logs, no server-side storage of summaries beyond a 1 h hashed cache                 |

Boundaries: browser to API (untrusted client), API to target site (hostile content, DNS and redirects), page text to LLM (untrusted data), API to Redis and providers (secrets).

## Threats and mitigations

| #   | Threat                                                                                                         | Mitigation                                                                                                                                                                                                                      | Verified by                                                                                     |
| --- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| T1  | SSRF to internal addresses (`localhost`, `169.254.169.254`, private ranges, IPv6 forms, decimal/hex/octal IPs) | Strict URL policy (http/https, ports 80 and 443, no credentials, no non-public names); `net.BlockList` over IPv4 and IPv6 including mapped, NAT64, 6to4, Teredo; fail closed on anything unparseable                            | 40+ case matrix, property tests vs an independent integer oracle, URL parser-differential cases |
| T2  | DNS rebinding                                                                                                  | All records resolved inside the socket `lookup`; any private record rejects; the connection uses the checked answer; re-checked every hop                                                                                       | `ssrf-guard` and `safe-fetch` tests with a flipping resolver                                    |
| T3  | Redirect to a private address, redirect loops, https to http downgrade                                         | Manual redirects, per-hop validation, 5-hop cap, downgrade refused; meta-refresh follows one validated hop                                                                                                                      | redirect tests, meta-refresh tests                                                              |
| T4  | Resource exhaustion: huge, slow, endless or compressed bodies                                                  | 2 MB cap enforced while streaming, 10 s total deadline, decompression output cap (gzip, brotli, deflate), content-type allowlist                                                                                                | tarpit, endless stream, gzip and brotli bomb tests                                              |
| T5  | Parser DoS: deeply nested markup, huge tag counts, JSON blobs full of HTML                                     | Linear markup pre-check before building a DOM; depth, node and container caps; bounded HTML conversions                                                                                                                         | 60k-nesting test (rejected in under 0.5 s; unguarded it took 150 s)                             |
| T6  | Quota or cost abuse                                                                                            | Per-client rate limit (Redis or memory), response cache, request body limit 4 KB, 50 s deadline, Vercel cancellation on disconnect                                                                                              | rate-limit, cache, burst tests                                                                  |
| T7  | Prompt injection from page content                                                                             | Page fenced with an unpredictable nonce and declared untrusted data; look-alike closing tags defused; invisible and bidi characters stripped; no tools, memory, secrets or other users in context; output rendered as text only | prompt tests, injection fixture, parser tests                                                   |
| T8  | XSS                                                                                                            | Plain-text pipeline end to end, React text rendering, lint rule forbidding `dangerouslySetInnerHTML`, `href` values are server-validated http(s), strict script CSP                                                             | unit and browser tests, CSP run with zero violations                                            |
| T9  | Secret leakage                                                                                                 | Keys only in server env; key in request header not URL; redaction in logs for Google, AI Studio, Groq and bearer formats; upstream error bodies never returned; `.env` git-ignored; `hygiene` secret scan                       | adapter and API tests, secret-scan script                                                       |
| T10 | Information leak through errors                                                                                | One mapper turns every error into a fixed, safe message; `detail` goes to logs only                                                                                                                                             | error-contract tests                                                                            |
| T11 | Self-recursion (submitting our own URL)                                                                        | Request host and Vercel hostnames are blocked as targets                                                                                                                                                                        | api test                                                                                        |
| T12 | Spoofed client IP to dodge the limiter                                                                         | Forwarded headers trusted only when running behind Vercel; value capped at 64 characters                                                                                                                                        | api test                                                                                        |
| T13 | Clickjacking, MIME sniffing, referrer leaks                                                                    | CSP `frame-ancestors 'none'`, `nosniff`, referrer and permissions policies, HSTS                                                                                                                                                | e2e header assertions                                                                           |
| T14 | CSRF                                                                                                           | No cookies and no ambient credentials; JSON content type required; no CORS headers                                                                                                                                              | api test                                                                                        |
| T15 | Supply chain                                                                                                   | Few dependencies, lockfile, `npm audit` in CI, no install-script dependencies we control, third-party agent skills vetted before use                                                                                            | audit output, decision record 15                                                                |
| T16 | Misleading summaries                                                                                           | Quote verification with explicit unverified labels; partial-extraction and truncation notices; refusal to summarize walls and challenge pages                                                                                   | grounding, page-quality tests                                                                   |

### Detailed mode (second model call)

| #   | Threat                                                             | Mitigation                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T17 | Injection that survives pass 1 inside the notes and reaches pass 2 | The notes are fenced with a nonce and declared untrusted data; look-alike closing tags are defused; pass 2 has no tools and no page text; its output is plain text. Every finding already had to quote the page.                          |
| T18 | A model inventing a finding, quote or figure                       | Code, not the model, decides what survives: quote must occur in the page, every figure must occur in the page, near-duplicates merge. The writer can only cite note ids that exist, and the evidence shown is the stored, verified quote. |
| T19 | Quota amplification (one request, two or more calls)               | Same per-client limit and cache; parts capped at 4; reading output capped at 100k characters; falls back to a single pass instead of retrying; request deadline unchanged.                                                                |

## Known limits (stated honestly)

- The in-memory rate limiter is best effort per serverless instance; the optional Upstash limiter is global.
- A page just under the tag limit (100k tags) can still cost a few seconds of synchronous CPU on one instance. Moving extraction to a worker thread with a hard stop is the next hardening step.
- Name resolution uses the system resolver; a black-holed nameserver can occupy its small thread pool for the OS timeout.
- Detailed mode spends the free quota roughly twice as fast as Quick (more for very long pages).
- There is no global daily budget for AI calls; the per-client limit, cache and circuit breaker are the protection.
- Verification proves a quote is present in the page, not that the summarized claim is correct.
- The same-origin policy and the lack of auth mean anyone can call the API from a server; that is by design, and the limits above are the protection.
- `style-src` allows inline styles because Material UI (Emotion) injects them at runtime. Scripts are `'self'` only.

## Reviews performed

1. Self review against the Cloudflare `security-audit` attack-class checklists (AI and LLM, resource exhaustion, client side, web protocol). Findings fixed: nested-markup DoS, unbounded CPU in extraction helpers, log redaction gap for a new key format, uncapped client-identifier length.
2. Research of real-world failure modes (bot challenges, consent walls, soft 404s, meta refresh, SSRF parser differentials, Vercel cancellation semantics, Gemini quota behaviour) with a test for each.
3. Two independent read-only reviews (backend security and reliability; frontend, accessibility and UX). Every finding was re-checked before acting. Confirmed and fixed, each with a regression test (`apps/api/test/review.test.ts` and the web unit tests):
   - Quadratic-time regexes in the thin-page helpers ran on raw hostile HTML before any structural check (a 400 KB page of `<` blocked the event loop for 50 s). Replaced with a linear scanner and bounded patterns.
   - Grounding accepted quotes with a changed number, an inserted negation, scrambled words or one repeated word. Fuzzy matches now need every number and negation, preserved word pairs, and at least three distinct words.
   - The markup pre-check counted `i<n` inside inline scripts as open tags and rejected real pages (HTTP 413). Script and style bodies are now skipped.
   - A dead or unparseable `<meta refresh>` target or `Location` header turned a good page into an error. The page is now used as is (a target blocked by the SSRF policy still errors).
   - Page titles are fenced like page text; pages with no words are refused; request deadline is 50 s so the typed timeout is sent before the platform limit; IPv6 clients are rate-limited per /64; SIIT and `3fff::/20` addresses are blocked; tag budget lowered to 100k.
   - Frontend: URLs ending in `)` were truncated, a late network reset replaced a finished result, a double click cancelled its own request, the sticky pane could hide the Summarize button on short windows, the result remounted when streaming ended, sticky header covered focused elements, CJK and short quotes could not be located, page text lacked `lang`, print output ignored the theme.
     Not changed: extraction CPU for pages near the tag limit (a worker thread would be the next step), the DNS thread pool under a black-holed resolver, and a global daily AI-quota budget. These are listed under known limits.

## Reporting

Open an issue without exploit details or contact the maintainer privately. If a secret is ever exposed, rotate it first.
